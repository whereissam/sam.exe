# AI observatory assets

`ai-observatory.blend` contains the cutaway circular room, telescope, shelves, and planter. `ai-explorer.blend` contains the wheeled parcel robot. Both are original procedural Blender models generated by `scripts/blender/build_observatory.py`.

Rebuild with:

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --threads 2 --python-exit-code 1 --python scripts/blender/build_observatory.py
```

The script writes editable Blender sources, texture-free GLBs, content-hashed copies in `public/models`, and `components/ai/model-manifest.json`. Rebuilding replaces the generated source files; save manual art edits separately.

The room is 587,276 bytes and the robot is 81,184 bytes. The expanded offline preview, including the floor, rounded equipment, parcels, conveyor and landscape, contains approximately 30,222 triangles. Runtime additions are authored in `ExperimentStations.tsx` and `WorkshopLandscape.tsx`; they are not baked into the original Blender room. Movement, obstacle editing, path indicators, and the carried parcel are controlled at runtime. The room is rendered on demand and robot motion stops when settled.

The experiment uses deterministic breadth-first search on a 7×7 grid. It is not connected to an LLM or robotics hardware. The controls describe this limitation to visitors.

## Dispatch simulation

The initial shift contains six color-coded cargo jobs with distinct pickup locations. Visitors can prioritize waiting cargo, add seeds/samples/parts, pause, single-step, and edit obstacles. A parcel already in transit completes before a priority change takes effect. Each delivery updates persistent station results; greenhouse growth, the sample scanner and the supply-chest lid remain interactive. A new shift resets the queue and layout.

Queueing and movement are pure functions in `components/ai/agent.ts`. The tests cover all six deliveries, adjacent movement, obstacle avoidance, priority while carrying, continued work after completion and intake capacity. The simulation is FIFO unless a visitor explicitly prioritizes a job; it does not claim learned scheduling or physical robot control.

The design draws on physical-AI simulation and digital-twin work described in [NVIDIA's March 2026 overview](https://blogs.nvidia.com/blog/gtc-2026-virtual-worlds-physical-ai/). No NVIDIA service or model is used at runtime.
